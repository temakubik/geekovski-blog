# GEEKOVSKI — блог на GitHub Pages

Статический сайт: заметки лежат в `content/posts/*.md`, генератор `build.py` собирает
готовый HTML в `docs/`, GitHub Pages раздаёт содержимое `docs/`.

## Как выпустить заметку

1. Создать файл `content/posts/<slug>.md`:

```
---
title: Заголовок
date: 2026-11-05 10:30
category: igry          # gadgets | kino | igry | ai
summary: Одно-два предложения лида.
cover:                          # /assets/img/xxx.jpg, если есть картинка
sources: Название — url | https://...; Второе издание | https://...
---

Текст в markdown. `## Заголовок раздела` — подзаголовок, `- пункт` — список,
**жирный**, *курсив*, [ссылка](https://...).
```

2. Собрать и проверить локально:

```
python3 build.py --theme editorial
cd docs && python3 -m http.server 8000
```

3. Закоммитить и запушить — Pages пересоберётся сам (30–60 секунд).

```
git add -A && git commit -m "post: <slug>" && git push
```

## Тема оформления

`--theme editorial|dashboard|magazine`. Выбранная тема фиксируется в `Makefile`/команде сборки.

## RSS для Дзена

Адрес после публикации: `https://geekovski.ru/dzen.xml`.
Сборка автоматически включает опубликованные статьи за последние 72 часа
по московскому времени (максимум 500). Черновики, дайджесты и будущие статьи
не передаются. `dzen: false` в front matter исключает отдельную статью.
Лента обновляется при каждой сборке сайта; её окно не сдвигается без пересборки.

Режим: `format-article`, автоматическая публикация сразу на канале.
`native-draft` не используется. `noindex` просит Дзен не индексировать копию
в поисковых системах. GUID совпадает с постоянным URL исходной статьи:
при правке не меняйте slug и дату, чтобы не создавать дубликаты.

Таблицы преобразуются в абзацы с названиями столбцов. В списках остаются
текст и адреса источников. В ленту попадают только проверенные локальные
изображения JPEG, PNG или GIF шириной от 700 px; непроверенные внешние
изображения пропускаются. Обычные `rss.xml`, `feed.xml` и `vk.xml` независимы.

Для подключения откройте в Дзен-студии настройки → «Свой сайт»:
подтвердите права на `https://geekovski.ru/`, затем в настройке трансляции
укажите `https://geekovski.ru/dzen.xml` и отправьте ленту на проверку.
Если Дзен предложит файл или метатег подтверждения, его нужно отдельно
добавить в сборку сайта — существующие подтверждения других сервисов
для этого не подходят. Само наличие файла RSS не подключает канал.

При первой отправке проверьте минимум 10 актуальных материалов в ленте
и минимум 3 публикации на сайте за месяц. После проверки новые материалы
будут публиковаться автоматически. По справке Дзена изменения исходной
статьи переносятся в течение 7 дней после первой загрузки, пока публикация
не редактировалась вручную в Студии.

Проверка адаптера: `python3 -m unittest discover -s tools -p 'test_dzen_feed.py'`.
Требования: [справка Дзена](https://dzen.ru/help/ru/website/rss-modify.html).

## Первый деплой (один раз)

1. Репозиторий `geekovski-blog` (public — Pages на бесплатном тарифе работает только там).
2. Settings → Pages → Source: **Deploy from a branch**, Branch: `main`, папка **/docs**.
3. Custom domain: `geekovski.ru` (без `https://`), Save. GitHub создаст файл `CNAME` в `docs/`.
4. Дождаться DNS check, включить **Enforce HTTPS**.
5. Settings → Pages → **Verify domain** → добавить в DNS TXT-запись
   `_github-pages-challenge-temakubik` со значением из окна → Verify. Запись не удалять.

## DNS (зона живёт на NS sprinthost: ns1–ns4.sprinthost.ru)

Правится в панели SprintHost (домен добавлен туда), либо переключением NS на REG.RU и
правкой в личном кабинете регистратора. Нужно:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | temakubik.github.io. |
| TXT | _github-pages-challenge-temakubik | (из окна Verify domain) |

Старую A-запись `109.196.165.85` удалить. Wildcard `*` не добавлять — риск захвата домена.
